## ¿Qué son los genéricos?

Los **genéricos** permiten definir clases, interfaces y métodos con un **parámetro de tipo** que se especifica al usarlos. El compilador usa ese tipo para verificar que los valores sean correctos, eliminando la necesidad de casting manual y previniendo `ClassCastException` en tiempo de ejecución.

Antes de Java 5, las colecciones trabajaban con `Object`:

```java
// ❌ Java anterior a 5 — sin seguridad de tipos
List lista = new ArrayList();
lista.add("Hola");
lista.add(123);           // ¡Esto compila pero es sospechoso!
String s = (String) lista.get(1); // ClassCastException en runtime
```

Con genéricos, el compilador detecta el error:

```java
// ✅ Java 5+ — seguro en compilación
List<String> lista = new ArrayList<>();
lista.add("Hola");
lista.add(123);  // Error de compilación: int no es String
String s = lista.get(0); // Sin casting necesario
```

## Clases genéricas

Una clase genérica se define con uno o más parámetros de tipo entre `<>`:

```java
public class Caja<T> {
    private T contenido;

    public void guardar(T valor) {
        this.contenido = valor;
    }

    public T obtener() {
        return contenido;
    }
}

// Uso:
Caja<String> caja = new Caja<>();
caja.guardar("Libro");
String item = caja.obtener(); // sin casting
```

Múltiples parámetros de tipo:

```java
public class Par<K, V> {
    private K clave;
    private V valor;

    public Par(K clave, V valor) {
        this.clave = clave;
        this.valor = valor;
    }

    public K getClave() { return clave; }
    public V getValor() { return valor; }
}

Par<Integer, String> p = new Par<>(1, "Uno");
```

## Métodos genéricos

Los métodos pueden ser genéricos incluso si la clase no lo es:

```java
public class Util {
    public static <T> T obtenerUltimo(List<T> lista) {
        return lista.get(lista.size() - 1);
    }

    public static <T> void intercambiar(T[] arr, int i, int j) {
        T temp = arr[i];
        arr[i] = arr[j];
        arr[j] = temp;
    }
}

// El compilador infiere el tipo:
String ultimo = Util.obtenerUltimo(List.of("A", "B", "C"));
```

## Bounded Type Parameters

Restringe los tipos permitidos a aquellos que extienden una clase o implementan una interfaz:

```java
// Solo acepta tipos que implementen Comparable
public static <T extends Comparable<T>> T maximo(T a, T b) {
    return a.compareTo(b) > 0 ? a : b;
}

// Uso:
System.out.println(maximo(10, 20));    // 20 (Integer implementa Comparable)
System.out.println(maximo("Ana", "Carlos")); // Carlos (String implementa Comparable)
```

## Wildcards (?), ? extends y ? super

### ? (wildcard ilimitado)

Acepta cualquier tipo:

```java
public static void imprimirLista(List<?> lista) {
    for (Object obj : lista) {
        System.out.println(obj);
    }
}
```

### ? extends T (covarianza — Producer Extends)

Puedes **leer** elementos como tipo `T`, pero no puedes **insertar**:

```java
// Acepta List<Integer>, List<Double>, etc.
public static double sumar(List<? extends Number> numeros) {
    double total = 0;
    for (Number n : numeros) {
        total += n.doubleValue();
    }
    return total;
}

// ✅ Puedes leer como Number
// ❌ numeros.add(10) — no compila
```

### ? super T (contravarianza — Consumer Super)

Puedes **insertar** elementos de tipo `T`, pero al leer obtienes `Object`:

```java
// Puedes agregar Integer o cualquier subtipo
public static void llenar(List<? super Integer> lista) {
    lista.add(10);
    lista.add(20);
    // Integer i = lista.get(0); // ❌ No compila
    Object obj = lista.get(0);    // ✅ Solo Object
}
```

### Principio PECS

**P**roducer **E**xtends, **C**onsumer **S**uper:

- Si un parámetro **produce** valores (los lees), usa `? extends T`
- Si un parámetro **consume** valores (los escribes), usa `? super T`

```java
// Ejemplo real: Collections.copy()
public static <T> void copy(
    List<? super T> dest,   // consumer: escribe aquí
    List<? extends T> src   // producer: lee de aquí
) { ... }
```

## Type Erasure

Java implementa genéricos mediante **type erasure**: el compilador borra la información de tipo genérico en el bytecode.

```java
// En código fuente:
List<String> lista = new ArrayList<>();

// Después de type erasure (en bytecode):
List lista = new ArrayList();
```

Esto significa que en tiempo de ejecución **no puedes** saber si una lista es `List<String>` o `List<Integer>`.

## Buenas prácticas

1. **Usa genéricos siempre** en colecciones — nunca raw types como `List` sin parámetro
2. **Nombra parámetros de tipo** con letras mayúsculas: `T` (type), `E` (element), `K`/`V` (key/value), `N` (number)
3. **Prefiere `? extends T`** para parámetros de solo lectura
4. **Usa el operador diamante `<>`** desde Java 7+
5. **Evita casting** con genéricos — si necesitas casting, algo está mal diseñado

## Errores frecuentes

### Error 1: Raw types
```java
// ❌ Raw type — sin seguridad de tipos
List lista = new ArrayList();

// ✅ Genérico
List<String> lista = new ArrayList<>();
```

### Error 2: Creer que `List<Integer>` es subclase de `List<Number>`
```java
// ❌ No compila — los genéricos son invariantes
List<Integer> enteros = new ArrayList<>();
List<Number> numeros = enteros; // Error

// ✅ Usa wildcard si necesitas flexibilidad
List<? extends Number> numeros = enteros;
```

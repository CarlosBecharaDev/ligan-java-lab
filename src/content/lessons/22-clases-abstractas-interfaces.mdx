## ¿Qué es una Clase Abstracta?

Una **clase abstracta** es una clase que no puede instanciarse directamente. Sirve como molde base para otras clases. Puede contener métodos abstractos (sin cuerpo) y métodos concretos (con implementación).

```java
// No se puede hacer: new Forma() - Error de compilación
public abstract class Forma {
    String nombre;

    // Constructor (sí se puede tener)
    Forma(String nombre) {
        this.nombre = nombre;
    }

    // Método abstracto: sin cuerpo, las subclases DEBEN implementarlo
    abstract double calcularArea();

    // Método concreto: tiene implementación
    void mostrar() {
        System.out.println(nombre + " - Área: " + calcularArea());
    }
}
```

**Reglas de clases abstractas:**
- Se declara con la palabra `abstract`
- No puede crear objetos con `new`
- Puede tener constructores (que llaman las subclases con `super`)
- Puede tener atributos normales
- Los métodos abstractos no tienen cuerpo (terminan en `;`)

## Métodos Abstractos

Un **método abstracto** es un método sin implementación. Las clases hijas están obligadas a implementarlo:

```java
public abstract class Animal {
    String nombre;

    Animal(String nombre) {
        this.nombre = nombre;
    }

    // Método abstracto: sin cuerpo
    abstract void hacerSonido();

    // Método concreto: con cuerpo
    void dormir() {
        System.out.println(nombre + " está durmiendo");
    }
}

// La subclase DEBE implementar hacerSonido()
public class Perro extends Animal {
    Perro(String nombre) {
        super(nombre);
    }

    @Override
    void hacerSonido() {
        System.out.println("Guau guau");
    }
}
```

## ¿Qué es una Interfaz?

Una **interfaz** define un contrato: qué métodos debe tener una clase, sin importar cómo se implementan. Es como un checklist que una clase se compromete a cumplir.

```java
// Interfaz: solo define qué se debe hacer, no cómo
public interface Notificable {
    void enviarNotificacion(String mensaje);
    boolean estaActiva();
}

// Una clase implementa la interfaz y define el "cómo"
public class Paciente implements Notificable {
    String nombre;
    boolean activo;

    Paciente(String nombre) {
        this.nombre = nombre;
        this.activo = true;
    }

    @Override
    public void enviarNotificacion(String mensaje) {
        System.out.println("Notificando a " + nombre + ": " + mensaje);
    }

    @Override
    public boolean estaActiva() {
        return activo;
    }
}
```

**Reglas de interfaces:**
- Se declara con `interface` en lugar de `class`
- Las clases la adoptan con `implements`
- Los métodos son `public` por defecto
- No puede tener constructores
- No puede tener atributos de instancia (solo `public static final`)

## implements: Múltiples Interfaces

Una clase puede implementar **varias interfaces** al mismo tiempo. Esto permite que un objeto cumpla múltiples contratos:

```java
public interface Pagable {
    double calcularPago();
    String metodoPago();
}

public interface Descontable {
    double aplicarDescuento(double porcentaje);
}

// Un producto puede ser pagable Y descontable
public class Producto implements Pagable, Descontable {
    String nombre;
    double precio;

    Producto(String nombre, double precio) {
        this.nombre = nombre;
        this.precio = precio;
    }

    @Override
    public double calcularPago() {
        return precio;
    }

    @Override
    public String metodoPago() {
        return "Tarjeta de crédito";
    }

    @Override
    public double aplicarDescuento(double porcentaje) {
        return precio * (1 - porcentaje / 100);
    }
}
```

## Métodos Default en Interfaces

Desde Java 8, las interfaces pueden tener métodos `default` con implementación propia. Esto permite agregar nuevas funcionalidades sin romper el código existente:

```java
public interface Logueable {
    void log(String mensaje);

    // Método default: ya viene con implementación
    default void logError(String error) {
        System.out.println("[ERROR] " + error);
    }

    default void logInfo(String info) {
        System.out.println("[INFO] " + info);
    }
}

public class Servicio implements Logueable {
    @Override
    public void log(String mensaje) {
        System.out.println("[LOG] " + mensaje);
    }

    // logError() y logInfo() ya están implementados por default
    // No es obligatorio sobreescribirlos
}
```

    double sumar(double a, double b);
    double restar(double a, double b);

    // Método default: calcula el promedio usando sumar y restar

        return sumar(a, b) / 2;
    }

    // Método default: muestra la resta con formato
    default String restarMostrar(double a, double b) {

    }

    @Override
    public double sumar(double a, double b) {
        return a + b;
    }

    @Override
    public double restar(double a, double b) {
        return a - b;
    }

    // promedio() y restarMostrar() ya vienen implementados
}

public class Main {
    public static void main(String[] args) {
        CalculadoraBasica calc = new CalculadoraBasica();

        System.out.println(calc.sumar(10, 5));       // 15.0
        System.out.println(calc.restar(10, 5));       // 5.0
        System.out.println(calc.promedio(10, 5));     // 7.5
        System.out.println(calc.restarMostrar(10, 5)); // 10.0 - 5.0 = 5.0
    }
}`}

## Cuándo Usar Cada Una

| Situación | Usa Clase Abstracta | Usa Interfaz |
|-----------|---------------------|--------------|
| Compartir código entre subclases | Si | No |
| Necesitas atributos o constructor | Si | No |
| Relación "es-un tipo de" | Si | No |
| Definir un contrato sin implementación | No | Si |
| Una clase necesita múltiples contratos | No | Si |
| Agregar funcionalidad sin romper código | No | Si (default) |

---

## Resumen

| Concepto | Descripción |
|----------|-------------|
| **Clase abstracta** | Clase que no se instancia; sirve como molde |
| **Método abstracto** | Método sin cuerpo que las subclases deben implementar |
| **Interfaz** | Contrato que define qué métodos debe tener una clase |
| **implements** | Palabra clave para adoptar una interfaz |
| **Múltiples interfaces** | Una clase puede implementar varias interfaces |
| **Método default** | Método en interfaz con implementación propia |

<details>
<summary>¿Qué pasa si una interfaz tiene métodos default con el mismo nombre?</summary>
Si una clase implementa dos interfaces con un método `default` igual, la clase DEBE sobreescribir ese método para resolver la ambigüedad. Puede llamar a la versión de cualquiera de las dos interfaces con `InterfazA.super.metodo()`.
</details>

<details>
<summary>¿Puedo heredar de una clase e implementar una interfaz a la vez?</summary>
Sí. En Java una clase solo puede extender una clase (extends), pero puede implementar múltiples interfaces. Sintaxis: `public class MiClase extends Padre implements A, B, C { }`
</details>

<details>
<summary>¿Cuándo no debo usar clase abstracta?</summary>
Cuando solo necesitas definir un contrato sin compartir código entre clases. En ese caso, una interfaz es más flexible porque permite que una clase implemente varias interfaces.
</details>

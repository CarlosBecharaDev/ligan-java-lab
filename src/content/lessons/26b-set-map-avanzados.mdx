## Set: colecciones sin duplicados

La interfaz `Set` representa una colección que **no permite elementos duplicados**. No hay orden garantizado a menos que uses una implementación específica. Pertenece al framework Collection y es ideal para modelar conjuntos matemáticos.

### HashSet

`HashSet<E>` es la implementación más usada de `Set`. Usa una tabla hash internamente para ofrecer rendimiento **O(1)** en operaciones básicas (`add`, `remove`, `contains`). No garantiza orden de los elementos.

```java
Set<String> nombres = new HashSet<>();
nombres.add("Ana");
nombres.add("Carlos");
nombres.add("Ana");        // ignorado silenciosamente
nombres.add("Beatriz");

System.out.println(nombres);          // [Ana, Carlos, Beatriz] (orden variable)
System.out.println(nombres.size());   // 3
System.out.println(nombres.contains("Carlos")); // true
```

### TreeSet

`TreeSet<E>` implementa `NavigableSet` y mantiene los elementos **ordenados** según su orden natural (`Comparable`) o un `Comparator` externo. Operaciones en **O(log n)**.

```java
TreeSet<Integer> numeros = new TreeSet<>();
numeros.add(30);
numeros.add(10);
numeros.add(50);
numeros.add(20);
numeros.add(30);           // ignorado

System.out.println(numeros);         // [10, 20, 30, 50] (ordenados)
System.out.println(numeros.first()); // 10
System.out.println(numeros.last());  // 50
System.out.println(numeros.ceiling(25)); // 30 (mayor o igual)
System.out.println(numeros.floor(25));   // 20 (menor o igual)
```

## Map avanzado: más allá de HashMap

Ya conoces `HashMap`. Ahora veamos sus variantes con orden.

### LinkedHashMap: orden de inserción

`LinkedHashMap<K,V>` mantiene una lista doblemente enlazada de las entradas, preservando el **orden de inserción**. Ofrece rendimiento similar a HashMap (O(1)).

```java
Map<String, Integer> edades = new LinkedHashMap<>();
edades.put("Ana", 25);
edades.put("Carlos", 30);
edades.put("Beatriz", 22);

System.out.println(edades);
// {Ana=25, Carlos=30, Beatriz=22} (orden de inserción)
```

**LRU Cache con LinkedHashMap:**

```java
class LRUCache<K,V> extends LinkedHashMap<K,V> {
    private final int maxSize;

    public LRUCache(int maxSize) {
        super(16, 0.75f, true); // accessOrder = true
        this.maxSize = maxSize;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K,V> eldest) {
        return size() > maxSize;
    }
}
```

### TreeMap: claves ordenadas

`TreeMap<K,V>` implementa `NavigableMap` y mantiene las claves **ordenadas**. Operaciones en **O(log n)**.

```java
TreeMap<String, Double> productos = new TreeMap<>();
productos.put("Laptop", 1200.00);
productos.put("Mouse", 25.50);
productos.put("Teclado", 89.99);

System.out.println(productos);
// {Laptop=1200.0, Mouse=25.5, Teclado=89.99} (orden alfabético)

System.out.println(productos.firstKey());      // Laptop
System.out.println(productos.lastKey());       // Teclado
System.out.println(productos.headMap("M"));    // {Laptop=1200.0}
System.out.println(productos.tailMap("M"));    // {Mouse=25.5, Teclado=89.99}
```

## Jerarquía completa de Map

```
Map<K,V>
├── HashMap        — Sin orden, O(1)
│   └── LinkedHashMap — Orden de inserción/ acceso
├── TreeMap        — Orden natural/comparador, O(log n)
├── ConcurrentHashMap  — Thread-safe, O(1)
└── Hashtable      — Legacy, thread-safe, lento
```

## Cuándo usar cada uno

| Situación | Implementación |
|-----------|---------------|
| Sin duplicados, sin orden | `HashSet` |
| Sin duplicados, ordenados | `TreeSet` |
| Clave-valor rápido | `HashMap` |
| Clave-valor con orden de inserción | `LinkedHashMap` |
| Clave-valor ordenado por clave | `TreeMap` |
| LRU Cache | `LinkedHashMap` con accessOrder=true |
| Concurrencia | `ConcurrentHashMap` |

## Errores frecuentes

### Error 1: Usar HashMap cuando necesitas orden
```java
// ❌ HashMap no garantiza orden
Map<String, Integer> map = new HashMap<>();

// ✅ LinkedHashMap preserva orden de inserción
Map<String, Integer> map = new LinkedHashMap<>();

// ✅ TreeMap mantiene orden por clave
Map<String, Integer> map = new TreeMap<>();
```

### Error 2: Modificar un Set mientras se itera
```java
Set<String> set = new HashSet<>(Set.of("A", "B", "C"));

// ❌ ConcurrentModificationException
for (String s : set) {
    if (s.equals("B")) set.remove(s);
}

// ✅ Usar Iterator.remove() o removeIf()
set.removeIf(s -> s.equals("B"));
```

## Buenas prácticas

1. **Programa contra interfaces**: `Set<String> set = new HashSet<>()`, no `HashSet<String> set`
2. **Elige la implementación por el caso de uso**, no por costumbre
3. **TreeSet/TreeMap requieren** que los elementos implementen `Comparable` o pasar un `Comparator`
4. **Sobrescribe `hashCode()` y `equals()`** correctamente al usar objetos propios en HashSet/HashMap
5. **Usa `Set.of()` y `Map.of()`** para colecciones inmutables pequeñas (Java 9+)

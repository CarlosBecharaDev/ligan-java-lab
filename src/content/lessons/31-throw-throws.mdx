## throw — lanzar excepciones

`throw` crea y lanza una excepción. El flujo del programa se detiene en ese punto y busca un `catch` que maneje la excepción:

<CodeBlock lang="java" title="throw para lanzar excepciones">
{`public class ThrowBasico {
    static void dividir(int a, int b) {
        if (b == 0) {
            throw new ArithmeticException("No se puede dividir por cero");
        }
        System.out.println(a + " / " + b + " = " + (a / b));
    }

    public static void main(String[] args) {
        dividir(10, 2);   // funciona
        dividir(10, 0);   // lanza excepción
    }
}`}
</CodeBlock>

**Salida esperada:**
```
10 / 2 = 5
Exception in thread "main" java.lang.ArithmeticException: No se puede dividir por cero
```

## throws — declarar excepciones

`throws` en la firma del método indica que puede lanzar una excepción que el llamador debe manejar:

<CodeBlock lang="java" title="throws en la firma del método">
{`import java.io.*;

public class ThrowsDemo {
    static String leerPrimeraLinea(String ruta) throws IOException {
        // Declara que puede lanzar IOException (checked)
        BufferedReader br = new BufferedReader(new FileReader(ruta));
        String linea = br.readLine();
        br.close();
        return linea;
    }

    public static void main(String[] args) {
        try {
            String contenido = leerPrimeraLinea("datos.txt");
            System.out.println("Primera línea: " + contenido);
        } catch (IOException e) {
            System.out.println("No se pudo leer: " + e.getMessage());
        }
    }
}`}
</CodeBlock>

## Propagación de excepciones

Cuando un método no maneja una excepción, esta se **propaga** hacia arriba por la pila de llamadas:

<CodeBlock lang="java" title="Propagación por la pila de llamadas">
{`public class Propagacion {
    static void nivel3() {
        throw new RuntimeException("Error en nivel 3");
    }

    static void nivel2() {
        nivel3();  // no maneja la excepción, se propaga
    }

    static void nivel1() {
        nivel2();  // tampoco la maneja
    }

    public static void main(String[] args) {
        try {
            nivel1();  // aquí se maneja
        } catch (RuntimeException e) {
            System.out.println("Atrapado en main: " + e.getMessage());
        }
    }
}`}
</CodeBlock>

**Salida esperada:**
```
Atrapado en main: Error en nivel 3
```

## Excepciones con causa (chaining)

<CodeBlock lang="java" title="Encadenar excepciones con initCause">
{`public class ExcepcionCausa {
    static void procesar() throws Exception {
        try {
            int x = Integer.parseInt("abc");
        } catch (NumberFormatException e) {
            Exception nueva = new Exception("Error procesando datos");
            nueva.initCause(e);  // conserva la causa original
            throw nueva;
        }
    }

    public static void main(String[] args) {
        try {
            procesar();
        } catch (Exception e) {
            System.out.println("Error: " + e.getMessage());
            System.out.println("Causa: " + e.getCause());
        }
    }
}`}
</CodeBlock>

**Salida esperada:**
```
Error: Error procesando datos
Causa: java.lang.NumberFormatException: For input string: "abc"
```

## Convenciones de creación de excepciones

```java
// ✅ Buena práctica: mensaje descriptivo
throw new IllegalArgumentException(
    "El precio no puede ser negativo: " + precio);

// ❌ Mal: mensaje genérico
throw new IllegalArgumentException("Error");

// ✅ Incluir el valor problemático
throw new IndexOutOfBoundsException(
    "Índice: " + index + ", Tamaño: " + size);

// ✅ Usar clases específicas
throw new FileNotFoundException("Archivo: " + ruta);
```

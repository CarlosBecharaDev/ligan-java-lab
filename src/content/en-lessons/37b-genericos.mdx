## What are generics?

**Generics** let you define classes, interfaces, and methods with a **type parameter** that is specified when you use them. The compiler uses that type to verify that the values are correct, eliminating the need for manual casting and preventing `ClassCastException` at runtime.

Before Java 5, collections worked with `Object`:

```java
// ❌ Pre-Java 5 — no type safety
List lista = new ArrayList();
lista.add("Hola");
lista.add(123);           // This compiles but it's suspicious!
String s = (String) lista.get(1); // ClassCastException at runtime
```

With generics, the compiler detects the error:

```java
// ✅ Java 5+ — safe at compile time
List<String> lista = new ArrayList<>();
lista.add("Hola");
lista.add(123);  // Compilation error: int is not String
String s = lista.get(0); // No casting needed
```

## Generic classes

A generic class is defined with one or more type parameters between `<>`:

```java
public class Caja<T> {
    private T contenido;

    public void guardar(T valor) {
        this.contenido = valor;
    }

    public T obtener() {
        return contenido;
    }
}

// Usage:
Caja<String> caja = new Caja<>();
caja.guardar("Libro");
String item = caja.obtener(); // no casting
```

Multiple type parameters:

```java
public class Par<K, V> {
    private K clave;
    private V valor;

    public Par(K clave, V valor) {
        this.clave = clave;
        this.valor = valor;
    }

    public K getClave() { return clave; }
    public V getValor() { return valor; }
}

Par<Integer, String> p = new Par<>(1, "Uno");
```

## Generic methods

Methods can be generic even if the class is not:

```java
public class Util {
    public static <T> T obtenerUltimo(List<T> lista) {
        return lista.get(lista.size() - 1);
    }

    public static <T> void intercambiar(T[] arr, int i, int j) {
        T temp = arr[i];
        arr[i] = arr[j];
        arr[j] = temp;
    }
}

// The compiler infers the type:
String ultimo = Util.obtenerUltimo(List.of("A", "B", "C"));
```

## Bounded Type Parameters

Restricts the allowed types to those that extend a class or implement an interface:

```java
// Only accepts types that implement Comparable
public static <T extends Comparable<T>> T maximo(T a, T b) {
    return a.compareTo(b) > 0 ? a : b;
}

// Usage:
System.out.println(maximo(10, 20));    // 20 (Integer implements Comparable)
System.out.println(maximo("Ana", "Carlos")); // Carlos (String implements Comparable)
```

## Wildcards (?), ? extends and ? super

### ? (unbounded wildcard)

Accepts any type:

```java
public static void imprimirLista(List<?> lista) {
    for (Object obj : lista) {
        System.out.println(obj);
    }
}
```

### ? extends T (covariance — Producer Extends)

You can **read** elements as type `T`, but you cannot **insert**:

```java
// Accepts List<Integer>, List<Double>, etc.
public static double sumar(List<? extends Number> numeros) {
    double total = 0;
    for (Number n : numeros) {
        total += n.doubleValue();
    }
    return total;
}

// ✅ You can read as Number
// ❌ numeros.add(10) — does not compile
```

### ? super T (contravariance — Consumer Super)

You can **insert** elements of type `T`, but when reading you get `Object`:

```java
// You can add Integer or any subtype
public static void llenar(List<? super Integer> lista) {
    lista.add(10);
    lista.add(20);
    // Integer i = lista.get(0); // ❌ Does not compile
    Object obj = lista.get(0);    // ✅ Only Object
}
```

### PECS principle

**P**roducer **E**xtends, **C**onsumer **S**uper:

- If a parameter **produces** values (you read them), use `? extends T`
- If a parameter **consumes** values (you write to it), use `? super T`

```java
// Real example: Collections.copy()
public static <T> void copy(
    List<? super T> dest,   // consumer: writes here
    List<? extends T> src   // producer: reads from here
) { ... }
```

## Type Erasure

Java implements generics through **type erasure**: the compiler removes the generic type information in the bytecode.

```java
// In source code:
List<String> lista = new ArrayList<>();

// After type erasure (in bytecode):
List lista = new ArrayList();
```

This means that at runtime you **cannot** know whether a list is `List<String>` or `List<Integer>`.

## Best practices

1. **Always use generics** in collections — never raw types like `List` without a parameter
2. **Name type parameters** with uppercase letters: `T` (type), `E` (element), `K`/`V` (key/value), `N` (number)
3. **Prefer `? extends T`** for read-only parameters
4. **Use the diamond operator `<>`** since Java 7+
5. **Avoid casting** with generics — if you need casting, something is badly designed

## Common errors

### Error 1: Raw types
```java
// ❌ Raw type — no type safety
List lista = new ArrayList();

// ✅ Generic
List<String> lista = new ArrayList<>();
```

### Error 2: Believing that `List<Integer>` is a subclass of `List<Number>`
```java
// ❌ Does not compile — generics are invariant
List<Integer> enteros = new ArrayList<>();
List<Number> numeros = enteros; // Error

// ✅ Use a wildcard if you need flexibility
List<? extends Number> numeros = enteros;
```

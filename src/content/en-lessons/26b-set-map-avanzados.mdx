## Set: collections without duplicates

The `Set` interface represents a collection that **does not allow duplicate elements**. There is no guaranteed order unless you use a specific implementation. It belongs to the Collection framework and is ideal for modeling mathematical sets.

### HashSet

`HashSet<E>` is the most widely used implementation of `Set`. Internally it uses a hash table to offer **O(1)** performance for basic operations (`add`, `remove`, `contains`). It does not guarantee the order of elements.

```java
Set<String> nombres = new HashSet<>();
nombres.add("Ana");
nombres.add("Carlos");
nombres.add("Ana");        // silently ignored
nombres.add("Beatriz");

System.out.println(nombres);          // [Ana, Carlos, Beatriz] (variable order)
System.out.println(nombres.size());   // 3
System.out.println(nombres.contains("Carlos")); // true
```

### TreeSet

`TreeSet<E>` implements `NavigableSet` and keeps the elements **sorted** according to their natural order (`Comparable`) or an external `Comparator`. Operations in **O(log n)**.

```java
TreeSet<Integer> numeros = new TreeSet<>();
numeros.add(30);
numeros.add(10);
numeros.add(50);
numeros.add(20);
numeros.add(30);           // ignored

System.out.println(numeros);         // [10, 20, 30, 50] (sorted)
System.out.println(numeros.first()); // 10
System.out.println(numeros.last());  // 50
System.out.println(numeros.ceiling(25)); // 30 (greater or equal)
System.out.println(numeros.floor(25));   // 20 (less or equal)
```

## Advanced Map: beyond HashMap

You already know `HashMap`. Now let's see its variants with order.

### LinkedHashMap: insertion order

`LinkedHashMap<K,V>` maintains a doubly linked list of the entries, preserving the **insertion order**. It offers similar performance to HashMap (O(1)).

```java
Map<String, Integer> edades = new LinkedHashMap<>();
edades.put("Ana", 25);
edades.put("Carlos", 30);
edades.put("Beatriz", 22);

System.out.println(edades);
// {Ana=25, Carlos=30, Beatriz=22} (insertion order)
```

**LRU Cache with LinkedHashMap:**

```java
class LRUCache<K,V> extends LinkedHashMap<K,V> {
    private final int maxSize;

    public LRUCache(int maxSize) {
        super(16, 0.75f, true); // accessOrder = true
        this.maxSize = maxSize;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K,V> eldest) {
        return size() > maxSize;
    }
}
```

### TreeMap: sorted keys

`TreeMap<K,V>` implements `NavigableMap` and keeps the keys **sorted**. Operations in **O(log n)**.

```java
TreeMap<String, Double> productos = new TreeMap<>();
productos.put("Laptop", 1200.00);
productos.put("Mouse", 25.50);
productos.put("Keyboard", 89.99);

System.out.println(productos);
// {Laptop=1200.0, Mouse=25.5, Keyboard=89.99} (alphabetical order)

System.out.println(productos.firstKey());      // Laptop
System.out.println(productos.lastKey());       // Keyboard
System.out.println(productos.headMap("M"));    // {Laptop=1200.0}
System.out.println(productos.tailMap("M"));    // {Mouse=25.5, Keyboard=89.99}
```

## Complete Map hierarchy

```
Map<K,V>
├── HashMap        — No order, O(1)
│   └── LinkedHashMap — Insertion/access order
├── TreeMap        — Natural order/comparator, O(log n)
├── ConcurrentHashMap  — Thread-safe, O(1)
└── Hashtable      — Legacy, thread-safe, slow
```

## When to use each one

| Situation | Implementation |
|-----------|---------------|
| No duplicates, no order | `HashSet` |
| No duplicates, sorted | `TreeSet` |
| Fast key-value | `HashMap` |
| Key-value with insertion order | `LinkedHashMap` |
| Key-value sorted by key | `TreeMap` |
| LRU Cache | `LinkedHashMap` with accessOrder=true |
| Concurrency | `ConcurrentHashMap` |

## Frequent errors

### Error 1: Using HashMap when you need order
```java
// ❌ HashMap does not guarantee order
Map<String, Integer> map = new HashMap<>();

// ✅ LinkedHashMap preserves insertion order
Map<String, Integer> map = new LinkedHashMap<>();

// ✅ TreeMap keeps order by key
Map<String, Integer> map = new TreeMap<>();
```

### Error 2: Modifying a Set while iterating
```java
Set<String> set = new HashSet<>(Set.of("A", "B", "C"));

// ❌ ConcurrentModificationException
for (String s : set) {
    if (s.equals("B")) set.remove(s);
}

// ✅ Use Iterator.remove() or removeIf()
set.removeIf(s -> s.equals("B"));
```

## Best practices

1. **Program against interfaces**: `Set<String> set = new HashSet<>()`, not `HashSet<String> set`
2. **Choose the implementation based on the use case**, not by habit
3. **TreeSet/TreeMap require** elements to implement `Comparable` or pass a `Comparator`
4. **Override `hashCode()` and `equals()`** correctly when using your own objects in HashSet/HashMap
5. **Use `Set.of()` and `Map.of()`** for small immutable collections (Java 9+)

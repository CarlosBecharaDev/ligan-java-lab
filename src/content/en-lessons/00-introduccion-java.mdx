## What is Java?

Java is an **object-oriented programming language** that compiles to an intermediate code called *bytecode*. It was created by James Gosling at Sun Microsystems and released in 1996. Its motto "**Write Once, Run Anywhere**" (WORA) means that the same program runs on Windows, Linux or macOS without modifications.

Java is one of the most widely used languages in the business world: banking systems, Android apps, big data, microservices with Spring Boot, and more.

## The Java ecosystem: JDK, JRE and JVM

To program in Java you need three nested components:

```
┌────────────────────────────────────────────┐
│                   JDK                        │
│  (You need it to DEVELOP)                    │
│  ┌────────────────────────────────────────┐ │
│  │               JRE                        │ │
│  │  (You need it to RUN)                    │ │
│  │  ┌──────────────────────────────────┐   │ │
│  │  │              JVM                   │   │ │
│  │  │  (Interprets and runs bytecode)    │   │ │
│  │  └──────────────────────────────────┘   │ │
│  │  + Java standard libraries               │ │
│  └────────────────────────────────────────┘ │
│  + javac, debugger, dev tools                │
└────────────────────────────────────────────┘
```

### JDK — Java Development Kit

It is the complete kit to DEVELOP in Java. It includes:

- **`javac`**: the compiler that converts `.java` to `.class` (bytecode)
- **JRE**: the runtime environment
- **Debugger**: to debug code step by step
- **Tools**: `javadoc`, `jar`, `jlink`, etc.

It is installed by a developer on their machine.

### JRE — Java Runtime Environment

It is the environment to RUN already-compiled Java programs. It includes:

- **JVM**: the virtual machine
- **Standard libraries**: `java.lang`, `java.util`, `java.io`, etc.

It is installed by an end user who only wants to run Java applications.

### JVM — Java Virtual Machine

It is the heart of Java: it interprets and executes bytecode. It is specific to each operating system. The JVM is what makes WORA possible: the same `.class` works on any OS that has its own JVM.

## The compilation and execution process

```
┌─────────────────────┐      javac       ┌──────────────────┐      JVM       ┌──────────────────┐
│  HolaMundo.java      │ ───────────────► │  HolaMundo.class  │ ─────────────► │  Console output  │
│ (source code)        │   (compiler)     │   (bytecode)       │  (interpreter) │                    │
└─────────────────────┘                  └──────────────────┘                └──────────────────┘
```

1. **You write** the code in a `.java` file
2. **`javac`** compiles to bytecode in a `.class` file
3. **The JVM** interprets that bytecode and executes it

Bytecode is NOT native machine code. It is an intermediate format that the JVM interprets. That is why the same `.class` works on any operating system that has a JVM.

## Your first program: Hello World

<CodeBlock lang="java" title="HolaMundo.java">
{`public class HolaMundo {
    public static void main(String[] args) {
        System.out.println("Hello World with Java!");
    }
}`}
</CodeBlock>

### Breaking it down line by line

| Line | Explanation |
|-------|------------|
| `public class HolaMundo` | Declares a public class. The name must match EXACTLY the file name: `HolaMundo.java` |
| `public static void main(String[] args)` | Entry point method. The JVM looks for this exact signature to start executing |
| `System.out.println(...)` | Prints text to the console followed by a line break |
| `;` | Every statement ends with a semicolon (mandatory) |

### Breakdown of `public static void main(String[] args)`

| Word | Meaning |
|---------|------------|
| `public` | Accessible from outside the class (the JVM needs to call it) |
| `static` | Does not require creating an object to run |
| `void` | Returns no value |
| `main` | Method name — must be exactly `main` in lowercase |
| `String[] args` | Parameter that receives command-line arguments |

### Compile and run step by step

```bash
# 1. Compile: generates HolaMundo.class
javac HolaMundo.java

# 2. Run: the JVM interprets the bytecode
java HolaMundo
```

**Expected output:**
```
Hello World with Java!
```

## Naming conventions

| Element | Convention | Example |
|----------|-----------|---------|
| Class | **PascalCase** | `MiPrimerPrograma` |
| Method | **camelCase** | `calcularPromedio()` |
| Variable | **camelCase** | `nombreUsuario` |
| Constant | **UPPERCASE** | `MAX_INTENTOS` |
| Package | **lowercase** | `com.miempresa.app` |
| `.java` file | = public class | `MiClase.java` |

## Structure of a real project

```
my-project/
├── src/
│   └── main/
│       └── java/
│           └── com/empresa/app/
│               ├── Main.java
│               ├── models/
│               └── services/
├── pom.xml (or build.gradle)
└── README.md
```

In professional projects, code is organized into **packages** (folders that reflect the business domain) and managed with build tools such as Maven or Gradle.

## Common errors

### Error 1: File name does not match the class
```java
// File: holamundo.java
public class HolaMundo {  // ❌ Compilation error
}
// ✅ File must be named HolaMundo.java (exactly the same)
```

### Error 2: `main` misspelled
```java
public static void Main(String[] args) {  // ❌ Error: must be main (lowercase)
public static void main(String[] args) {   // ✅ Correct
}
```

### Error 3: Forgetting the semicolon
```java
System.out.println("Hola")  // ❌ Compilation error: missing ;
System.out.println("Hola"); // ✅ Correct
```

### Error 4: Confusing JDK with JRE
```bash
# Trying to compile with only JRE
java HolaMundo.java    # ❌ java runs .class, it doesn't compile
javac HolaMundo.java   # ✅ javac compiles (JDK only)
```

## How to install the JDK

1. Go to [adoptium.net](https://adoptium.net) and download **JDK 21 LTS** for your operating system
2. Run the installer (next, next, finish)
3. Verify the installation:
   ```bash
   java -version
   javac -version
   ```
4. Optional: install **IntelliJ IDEA Community** or **VS Code** with the Java extensions

## Best practices

1. **PascalCase for classes**: `MiClase`, not `miclase` or `mi_clase`
2. **One `.java` file per public class** with the same name
3. **Use LTS versions of the JDK** (21 is the most recent)
4. **Learn to use an IDE** from the start: autocomplete, refactoring and debugging speed up learning

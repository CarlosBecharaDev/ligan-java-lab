## Debugging with println

The most basic and universal technique: printing values at strategic points:

<CodeBlock lang="java" title="Debugging with println">
{`public class DebugPrintln {
    static int factorial(int n) {
        System.out.println("factorial(" + n + ")");
        if (n == 0) return 1;
        int resultado = n * factorial(n - 1);
        System.out.println("  → factorial(" + n + ") = " + resultado);
        return resultado;
    }

    public static void main(String[] args) {
        System.out.println("Result: " + factorial(4));
    }
}`}
</CodeBlock>

**Expected output:**
```
factorial(4)
factorial(3)
factorial(2)
factorial(1)
factorial(0)
  → factorial(1) = 1
  → factorial(2) = 2
  → factorial(3) = 6
  → factorial(4) = 24
Result: 24
```

## Assertions (assert)

`assert` verifies conditions during development. They are enabled with the `-ea` flag:

```bash
java -ea MiPrograma
```

<CodeBlock lang="java" title="Assertions for debugging">
{`public class Aserciones {
    static double raizCuadrada(double n) {
        assert n >= 0 : "Cannot take the square root of a negative number: " + n;
        return Math.sqrt(n);
    }

    public static void main(String[] args) {
        System.out.println(raizCuadrada(25));  // 5.0
        System.out.println(raizCuadrada(-1));  // throws AssertionError with -ea
    }
}`}
</CodeBlock>

## The "divide and conquer" technique

To find a bug, keep removing parts of the code until you isolate the error:

1. **Comment out half the code** and test if the error persists
2. If it persists → the bug is in the uncommented half
3. If it disappears → the bug is in the commented half
4. **Repeat** until you isolate the bug

## Writing unit tests with JUnit 5

```java
// Calculadora.java
public class Calculadora {
    static int sumar(int a, int b) { return a + b; }
    static int restar(int a, int b) { return a - b; }
    static int multiplicar(int a, int b) { return a * b; }
    static int dividir(int a, int b) { return a / b; }
}
```

```java
// CalculadoraTest.java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

class CalculadoraTest {
    @Test
    void testSumar() {
        assertEquals(5, Calculadora.sumar(2, 3));
        assertEquals(-1, Calculadora.sumar(-2, 1));
        assertEquals(0, Calculadora.sumar(0, 0));
    }

    @Test
    void testDividir() {
        assertEquals(2, Calculadora.dividir(10, 5));
        assertThrows(ArithmeticException.class,
            () -> Calculadora.dividir(5, 0));
    }
}
```

## Reading a stack trace like an expert

```
Exception in thread "main" java.lang.NullPointerException
    └──────────────────────────────────────↕──┘
     Exception type                         Message

    at com.app.Paciente.nombre.toUpperCase(Paciente.java:42)
    └───────────────────┘
     What was attempted (nombre.toUpperCase on a null name)

    at com.app.Main.registrar(Main.java:15)
    at com.app.Main.main(Main.java:5)
    └── Stack of who called whom
```

**Steps:**
1. Identify the exception **type** (`NullPointerException`)
2. Read the **message** (null)
3. Go to the **first 'at' line** that is YOUR code (`Paciente.java:42`)
4. Open the file at the indicated line and look for what is `null`

## The "rubber duck" technique

Explain your code line by line to an inanimate object (a rubber duck). By verbalizing what each line does, you often find the error yourself without the duck saying anything.

## throw — throwing exceptions

`throw` creates and throws an exception. Program flow stops at that point and looks for a `catch` that handles the exception:

<CodeBlock lang="java" title="throw to throw exceptions">
{`public class ThrowBasico {
    static void dividir(int a, int b) {
        if (b == 0) {
            throw new ArithmeticException("Cannot divide by zero");
        }
        System.out.println(a + " / " + b + " = " + (a / b));
    }

    public static void main(String[] args) {
        dividir(10, 2);   // works
        dividir(10, 0);   // throws exception
    }
}`}
</CodeBlock>

**Expected output:**
```
10 / 2 = 5
Exception in thread "main" java.lang.ArithmeticException: Cannot divide by zero
```

## throws — declaring exceptions

`throws` in the method signature indicates that it may throw an exception that the caller must handle:

<CodeBlock lang="java" title="throws in the method signature">
{`import java.io.*;

public class ThrowsDemo {
    static String leerPrimeraLinea(String ruta) throws IOException {
        // Declares that it may throw IOException (checked)
        BufferedReader br = new BufferedReader(new FileReader(ruta));
        String linea = br.readLine();
        br.close();
        return linea;
    }

    public static void main(String[] args) {
        try {
            String contenido = leerPrimeraLinea("datos.txt");
            System.out.println("First line: " + contenido);
        } catch (IOException e) {
            System.out.println("Could not read: " + e.getMessage());
        }
    }
}`}
</CodeBlock>

## Exception propagation

When a method doesn't handle an exception, it **propagates** up the call stack:

<CodeBlock lang="java" title="Propagation up the call stack">
{`public class Propagacion {
    static void nivel3() {
        throw new RuntimeException("Error at level 3");
    }

    static void nivel2() {
        nivel3();  // doesn't handle the exception, it propagates
    }

    static void nivel1() {
        nivel2();  // doesn't handle it either
    }

    public static void main(String[] args) {
        try {
            nivel1();  // it's handled here
        } catch (RuntimeException e) {
            System.out.println("Caught in main: " + e.getMessage());
        }
    }
}`}
</CodeBlock>

**Expected output:**
```
Caught in main: Error at level 3
```

## Exceptions with a cause (chaining)

<CodeBlock lang="java" title="Chaining exceptions with initCause">
{`public class ExcepcionCausa {
    static void procesar() throws Exception {
        try {
            int x = Integer.parseInt("abc");
        } catch (NumberFormatException e) {
            Exception nueva = new Exception("Error processing data");
            nueva.initCause(e);  // preserves the original cause
            throw nueva;
        }
    }

    public static void main(String[] args) {
        try {
            procesar();
        } catch (Exception e) {
            System.out.println("Error: " + e.getMessage());
            System.out.println("Cause: " + e.getCause());
        }
    }
}`}
</CodeBlock>

**Expected output:**
```
Error: Error processing data
Cause: java.lang.NumberFormatException: For input string: "abc"
```

## Exception creation conventions

```java
// ✅ Good practice: descriptive message
throw new IllegalArgumentException(
    "The price cannot be negative: " + precio);

// ❌ Bad: generic message
throw new IllegalArgumentException("Error");

// ✅ Include the problematic value
throw new IndexOutOfBoundsException(
    "Index: " + index + ", Size: " + size);

// ✅ Use specific classes
throw new FileNotFoundException("File: " + ruta);
```
